# 回滾

正式環境出問題時，原則是先回滾、再查原因，不要直接在正式環境上除錯或熱修。回滾不需要等 reviewer 核可，任何一位值班人員都可以執行，但事後一定要補事故紀錄，說明回滾的原因與影響範圍。

## 回滾步驟

1. 找出上一個正常的版本：`acmectl releases --env prod` 會列出最近十次部署的時間與版本號。
2. 執行 `acmectl rollback --env prod --to v2.13.2`；不加 `--to` 時會退回上一個版本。
3. 回滾約需 3 分鐘，期間金絲雀流量會先切回舊版。完成後到 Grafana 確認 5xx 比例回到平常水準。
4. 在 #release 頻道公告回滾的原因與版本號，並開一張事故單。

## 資料庫 migration 怎麼辦

回滾只會換程式版本，不會自動倒回資料庫 migration。因為 migration 規定要向下相容（見發版流程的上線前檢查），舊版程式可以直接跑在新的 schema 上。真的需要倒回 schema 時，要找資料庫負責人手動處理，不要自己執行 `migrate down`。
